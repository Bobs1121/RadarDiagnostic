# radarAnalyze V3 核心产品蓝图：AI Triage (智能分诊系统)

> **版本**: 3.0.0-Refocused
> **核心定位**: 专注且极致的 **AI Triage (智能分诊与诊断)** 系统。

## 1. 核心目标 (Core Goal)
实现 ADAS 角雷达问题（如 FCTA未触发、迟滞等）的**自动化、智能化初期分析与根因分诊 (Triage)**。打通“需求 -> 代码 -> 数据”的分析链路，精准定位问题源头。

## 2. 核心架构与功能模块 (Strict Scope)

根据项目实际需求，系统严格划分为以下四大刚需模块：

### 模块 A: 异构数据解析与可视化 (Data Extraction & Plotting)
- **输入**: 客户提供的 `.bag`, `.blf`, `.mf4` 数据。
- **功能**: 支持独立或被组合使用。能够根据自然语言意图或指定名称，精准拉取相关信号并完成可视化出图，用于问题的初期人工或 AI 分析。
- **实现栈**: DuckDB/asammdf (时序数据), cantools (DBC 解析)。

### 模块 B: Core + COEM 项目隔离与模块化 (Workspace Modularity)
- **概念**: 项目具备模块化与独立配置能力，区分公共代码（Core）与客户代码（COEM）。
- **原则**: 客户部分内容尽量小，最大化复用公共基线。
- **隔离资产**: 每个客户项目拥有独立的流程配置、DBC矩阵、需求定义、记忆沉淀。

### 3. 模块 C: 代码结构化与拓扑引擎 (Code Topology & Logic)
- **链路读取**: 采用**先写预编译拓扑图**（Pre-computed Topology），拒绝实时全量读取代码链路，避免上下文超载。
- **技术选型**: 采用 **CodeGraph (底层 AST 确切骨架) + LLI Wiki (大模型语义总结)** 的混合双擎。
- **功能**: 无数据输入时，也可作为独立的**代码开发助手**提供基于拓扑的问答。

### 4. 模块 D: Agentic 智能分诊主脑 (Agentic Triage Loop)
- **设计理念**: 学习 Codex/Claude Code。摒弃死板的静态代码管线。
- **功能**: LLM 作为大脑，动态调用上述模块（数据、图谱、DBC）作为 Tool。
- **闭环管理**: 将需求拆解、DBC 信号和代码链路进行关联，并自动沉淀历史分诊记忆（Memory System）用于后续流程优化。
