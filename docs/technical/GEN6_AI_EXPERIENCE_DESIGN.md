# Gen6 AI：完整旅程与交互设计

状态：目标设计；实时工作页与默认独立会话已由用户确认。关联 [产品基线](GEN6_AI_PRODUCT_BASELINE_2026-09-16.md)、[系统设计](GEN6_AI_SYSTEM_DESIGN.md)。

## 1. 贯穿全流程的体验标准

系统负责记忆配置、探测技术事实、准备工作、组织证据与恢复失败；用户负责提出问题、纠正业务意图、授权和工程取舍。每个页面或提问先检验：是否迫使用户重复输入、换算、搜索、切应用、等待未知进度，或理解内部实现。

自主不是隐瞒过程，稳定不是永不报错。任何时刻用户应知道：在处理什么、已得到什么、是否需要自己做事、离开后能否继续。不能将用户心智负担从分析转移到复杂配置、几十个工具选择或审批弹窗。

## 2. 全旅程责任表

| UX | 场景 | 系统自行完成 | 用户看到/需要做 | 失败与恢复 |
|---|---|---|---|---|
| UX01 | 首次启用 | 体检 Python/Pi/provider、SSH/workspace、harness、磁盘和版本兼容 | 一次连接与项目绑定；只显示影响当前任务的问题 | 精确修复建议；只读/本地可用能力继续，不要求重装全部 |
| UX02 | 输入 bag＋问题 | 识别路径/材料、复用配置、版本候选、数据去重与完整性 | 简短确认“车型/版本/问题/分析范围”，只有冲突才提问 | 给少量有来源的版本候选，不问 commit 哈希猜谜 |
| UX03 | 准备环境 | 权限范围内传输/隔离/配置/编译/探测，保留原环境 | 一个阶段计划和准备进度；无需逐条确认命令 | 断点续传/复用已完成步骤；重试不覆盖原数据 |
| UX04 | 事件定位 | 四雷达盘点，按问题聚类与选择；无报警时按场景找窗口 | 一句话问题范围与事件列表，可改焦点 | 缺失/未查明确，不把第一事件当唯一事件 |
| UX05 | L1 还原 | 真实场景、曲线、视频、输出时间与代码绑定 | 尽早看到相关事件，不必等待完整调查 | 缺视频/尺寸仍有有效视图；不使用伪数据补画 |
| UX06 | L2 调查 | 代码/数据检索，选择仿真及 GDB，排除候选，控制预算 | 持续更新“已确认/仍未知/下一步”，展开具体证据 | 自动有界替代取证；超时交付局部结果和续作 |
| UX07 | 工程裁决 | 准备影响、反证、行为解释与建议 | 只回答行为是否符合期望等业务问题 | 暂不判断可保存；不为得到肯定而反复问同一问题 |
| UX08 | L3 修改验证 | 准备验证标准、隔离 diff、构建回灌、变量/行为前后比较 | 审阅改动目的/风险并授权，必要时修订指标 | 编译失败不冒称修复；保留原版和失败尝试 |
| UX09 | 离开/中断/重开 | durable checkpoint、状态重连、所有权清理与恢复 | “继续此调查”及现状摘要，无需重述背景 | 失去连接不等于远端已停；恢复先核查执行状态 |
| UX10 | 交付与再利用 | 冻结报告与依赖包、保留可追溯来源、有效知识召回 | 可分享/归档报告，知道哪些未验证 | 导出缺视频/附件显式；默认不导出全部源码和大数据 |
| UX11 | 环境/版本变化 | 复核签名、识别失效产物，重新采集必要子集 | “版本改变，以下结论需重验”，可看旧版 | 不删除旧证据，不静默把旧结论带入新版本 |

## 3. 页面与导航

首期为 Pi 对话＋浏览器实时工作页，不建设账号/团队门户。案件页、历史案件列表、一次性环境设置构成最小导航；工程设置折叠，内部工具 catalog 仅供操作员。

案件页信息架构：

```text
案件：问题 / 车型与版本 / 状态 / 继续或停止
摘要：已确认什么 · 调查覆盖 · 当前是否需你决定
事件选择       场景/视频 + 同步时间线       当前发现与下一步
              关键曲线 ↔ 当前代码与值
展开区：赋值/调用链、实验、原始证据、执行日志
```

主区优先相关成果，不默认展示所有变量或全部调用图。窄窗口以场景/代码 tab 组织，不强制三栏。场景、代码、曲线的布局可切换，但共享选择状态。

实时成果更新不抢焦点、不重置缩放/滚动/所选事件。更新的结论标注“新增证据/修正”，不让用户误以为自己刚看过的值无故变化。历史版本冻结视图与当前视图显著区分。

## 4. 共享选择与动作语义

选择状态逻辑包含 run、事件、雷达、目标、时间范围/帧、证据层和源码快照；用户用业务名称操作，原始 ID 可展开。不存在可靠关联时显示独立视图，不强行联动。

- 点事件：同步场景、曲线与相关代码；不重新全量分析。
- 点变量：展示真实 token、值/来源/作用域、时间变化与写入消费者；可“继续调查此处”。
- 提问：“这次为什么报警”“换看右侧”：将当前选择上下文交给同一 Pi session/run，不开启独立聊天树。
- 用户确认/否定/无关：记录为 user observation，不升级为 runtime。
- 授权/取消：通过同一执行控制边界；浏览器不得拼接 shell 或把一个按钮直接等同 approved=true。

动作重复提交、页面刷新和网络重连使用幂等 request id；界面先显示请求处理中，收到权威状态后再显示运行/停止，不能乐观宣称远端已经停止。

## 5. 等待、打断与错误设计

显示真实阶段与已完成量，不编造百分比。耗时预估只有历史或当前吞吐依据时展示，十分钟目标与实际经过时间同时可见。后台多次尝试合并成一次用户可读更新，错误日志可展开。

用户问题按三类处理：业务歧义、授权、确实缺输入。提问携带已知事实、选项影响和推荐项，并说明什么工作仍在继续。等待回答仅暂停依赖分支；未经回答不能扩大授权或擅自决定业务口径。

可恢复错误先在预算内重试，确定性错误不盲重试；失败提示为“影响了什么/保留什么/接下来怎么做”。无网络、模型不可用、无符号、过期配置等不同原因不统一显示“分析失败”。

## 6. 基础交互质量

- 中文业务标签保留真实代码 token；支持搜索、复制变量/路径及可定位源码片段。
- 键盘可操作、清晰焦点、状态不只靠颜色；长表虚拟化/分页，图形保留单位和图例。
- 大 bag、视频与 trace 按窗口加载，避免页面一次载入 GB 数据；加载失败局部重试，不清空整个页面。
- 授权页展示变化范围和验证目标，不要求阅读整份 diff 才理解影响；详细 diff 仍可完整审阅。
- 原始数据与证据不可在 UI 中编辑成事实。用户注释、假设与实测分层。
- 离线报告冻结当前 revision，包含所需相对资源或清晰缺失说明，不依赖绝对工作区路径才能打开。

## 7. 体验验收方式

按 UX01～11 走真实任务，记录首次有效成果、业务决策用时、无必要提问数、手工搜索/换算/跨应用次数、恢复所需动作和错误理解。与同案例人工 arbe 流程比较；阈值用基线实测制定，不能用“用户习惯适应”解释不省时。

首页五个问题须可回答：输入/版本对吗；发生了什么；代码为何这样执行；哪些结论可信/未确认；现在需要我决定什么。任何一个答案必须让用户先阅读日志或自己拼接多份 JSON，则体验不通过。
