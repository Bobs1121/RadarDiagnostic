## 1. 开始方式

具体迭代执行以 [Sprint 计划](GEN6_AI_SPRINT_PLAN.md) 和 [持续开发规范](GEN6_AI_EXECUTION_PROTOCOL.md) 为准；最新 task/依赖/阻塞在 [执行状态](gen6_execution_state.v1.json)，恢复入口为 [Handoff](GEN6_AI_HANDOFF.md)。WP 定义责任域，Sprint 定义跨模块成果，不互相替代。旧文档已物理归档。

先保存当前工作树边界，按现有模块和真实调用路径建立“已实现/部分/缺失/未验证”矩阵。仓库存在大量进行中的修改，不能 reset、覆盖或把所有 diff 当作本任务成果。历史测试数量、handoff 和文档 ready 只能作为检索线索。

先核查现有能力是否能支撑用户行为，再决定最小修改；不能从零重写 Pi、证据账本、报告或 arbe 执行器。旧 US/PC-AC 追踪到新 G6-AC，继承证据必须核对版本、输入和测试层级。

WP1～WP4 同时记录性能；WP5 不作为最后才发现耗时问题的借口。优先完成一条真实 RCTB 类问题从输入到阶段成果的纵向链路，再用多事件、跨雷达、无报警与第二车型/版本检查泛化。第二车型/版本是工具隔离与泛化验收，不代表首期已要求日常跨数据集回归产品。

### 2.1 每包任务卡（开发前必填）

`用户可见问题 → R/UX/AC → 当前证据 → 拟改模块及契约 → 范围/非目标 → 独立验收 → 失败/恢复 → 性能与交互影响 → 兼容/迁移/回退 → 所需授权 → 完成证据`。

责任按模块划分，不按“写前端/写脚本”孤立交付。任何新增控件必须有权威状态与动作接口；任何新工具必须在真实 Pi 用户链路中证明价值。

### 2.2 实施、迁移和回退

先通过开关并存新实时视图与现有离线报告，两者读取同一 ledger。数据/接口兼容迁移先备份派生产物，旧 run 可读；未知 schema 明确不支持，不能静默改写历史。

部署前记录依赖版本、artifact/schema 兼容、活动会话和配置。失败回退应用/adapter 版本及配置，保留 ledger/证据，不回滚用户原始数据或自动重写算法历史。数据库/索引结构改变需可重建或明确迁移方案。

本轮未授权实际远程修改；实施者在计划具体后按任务范围取得授权。已有授权范围内连续完成，不按每条命令重复请求。

## 3. 原子工具实现准则

2026-09-16 痛点驱动调整：WP2/WP3 须联合交付“单个真实事件→真实代码表达式→同事件变量值→赋值/消费链→可判断的下一步”纵向切片，优先于增加更多报告章节或工具数量。WP4 必须沿用该组变量做修改前后对照。G6-AC12/13 是交付门，不得以报告生成成功代替。

1. 对照 registry/catalog 核查现有工具；新增时明确单一责任、输入来源、输出上限、ModuleResult 与失败语义。
2. 所需身份、run_id、artifact 路径由上下文/bridge 自动绑定，不增加用户或 Pi 记忆技术字段的负担。
3. 读工具不能偷偷编译/回放；计划工具不能声称执行已成功。执行权限在可信边界检查，不依赖 prompt 自律。
4. 执行器拥有 reset/预热/完成确认/超时/取消/清理责任；分析模块不复制 shell、SSH、ROS 生命周期逻辑。
5. Pi 决定调查路径，确定性工具不硬编码 RCTB 根因、候选排名或必须通过的条件数。
6. 修改公开 schema、缓存或 API 时同步对应 AGENTS.md 和消费者；不因本次文档工作而无关修改运行代码。

## 4. 验证策略

| 层级 | 验证内容 | 不能替代 |
|---|---|---|
| 单元/契约 | 布局、单位、枚举、身份、边界、错误/部分结果 | 真实算法执行 |
| 独立数据对照 | 可信解码器/人工核验/参考字段，记录来源与误差；不能只用实现自身公式生成期望值 | 用户业务判断 |
| 集成 | Pi 注册、bridge、上下文、工具输入输出、恢复与授权 | 真实模型选择与远程回放 |
| 真实回放/GDB | 两种模式、雷达选择、基线复现、预热/完成、内部变量和证据 | 多轮产品交互与报告可用性 |
| Pi 产品验收 | 自然语言请求→自主工具选择→阶段成果→追问→结论/裁决 | 准确性独立对照 |
| 报告验收 | 浏览器打开、事件选择、播放/曲线/代码联动、视频对齐与缺值表现 | 因果正确性 |

最小验收样本组合应包含：多雷达多事件、已知根因、正常/性能取舍、证据不足、无报警问题、目标级及点云执行、版本/配置变化、接近输入上限数据。样本可复用，但每项 AC 记录实际覆盖，不能假定同一成功案例覆盖所有异常路径。

错误路径包括截断/错版本布局、帧域不一致、对象 ID 复用、占位值、未知坐标、断点不命中/optimized_out、用户中止、进程冲突、模型/SSH 失败、超时、缓存 stale。不得为了通过异常测试删除仍可用的证据。

## 5. 性能测量要求

测试前登记实际字节数、录制时长、雷达/事件/视频规模、运行机器与存储、模型、代码/配置/binary 和缓存条件。用户的 10gb 按十进制 GB 或 GiB 的测试标注分别写明实际字节，不无声改变输入上限。

记录环境准备、读取/hash/索引、代码检索、模型、编译、回放、GDB、报告耗时与峰值资源；报告端到端、分析墙钟、明确用户等待和 L3 时间。重复次数在测量计划预先登记，报告每次结果及 p50/p95/最大值；失败/超时样本纳入完成率，不能从样本表删除。

十分钟目标未达则定位主要成本，并验证优化前后准确性相同。吞吐和证据下限必须同时满足，不能降低帧覆盖、改变输入或取消必要历史预热来制造达标。
