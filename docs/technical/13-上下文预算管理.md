# ContextBudget — 上下文预算管理

## 职责

解决专家面板 prompt 过长问题。历史上每个证据片段各自截断到 `max_chars`，但没有全局上限，复杂 case 下最终 prompt 能膨胀到 80KB+。

过长 prompt 的副作用：
- 稀释模型注意力
- Token 成本线性增长
- 可能超出远程模型的上下文窗口

## 设计

`ContextBudget` 接受一个总字符预算（默认 60KB）和一组命名的证据片段及其优先级。当所有内容都能容纳时直接拼接；超出预算时，按优先级从低到高截断，每个片段至少保留 `min_chars` 保底长度。

## 优先级建议

| 优先级 | 片段类型 | 说明 |
|--------|---------|------|
| 100 | evidence / KEY_FACTS / timeline | 实际发生了什么（最重要） |
| 90 | TPE block / suppression / output signals | 直接因果证据 |
| 80 | memory_context | L1-L6 记忆系统上下文 |
| 70 | threshold_reference | 该功能的阈值文档 |
| 60 | conditions_text | 激活条件 |
| 50 | data_summary / inventory | 数据摘要 |
| 40 | parameter analysis | 参数分析 |

## API

```python
budget = ContextBudget(total_chars=60_000)
budget.add("evidence", evidence_text, priority=100, min_chars=8_000)
budget.add("memory", memory_context, priority=80, min_chars=3_000)
budget.add("threshold", threshold_ref, priority=70, min_chars=1_500)

sections = budget.render()       # → list[(name, truncated_text)]
report = budget.format_report()  # → 人类可读的预算使用报告
text = budget.concat("\n\n")     # → 拼接为单字符串
```

## 截断算法

```
1. 如果总大小 <= 预算 → 全量返回，不截断
2. 否则:
   a. 按优先级 DESC 排序
   b. 预先为每个片段预留 min_chars (保底池)
   c. 剩余预算分配给高优先级片段，从最高开始贪婪分配
   d. 超出预算的片段截断到 allowed 长度，尾部加 "... [truncated]"
   e. 返回保持原始插入顺序
```

## 数据结构

```python
@dataclass
class _Piece:
    name: str
    content: str
    priority: int = 50
    min_chars: int = 500
    rendered: str = ""      # render() 后填充
    truncated: bool = False

@dataclass
class ContextBudget:
    total_chars: int = 60_000
    pieces: list[_Piece]
```

## 预算报告

```python
def format_report(self) -> str:
    """
    输出格式:
    Context budget: 60,000 chars
      [100] evidence             15,234 /  15,234 chars
       [90] tpe_block             8,102 /   8,102 chars
       [80] memory               12,000 /  18,500 chars ⚠trimmed
       [60] conditions            5,000 /   5,000 chars
      TOTAL rendered: 40,336 chars (67.2% of budget)
    """
```
