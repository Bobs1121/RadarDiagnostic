# 数据解析层 — Parsers & FrameStore

## 职责

将原始录制数据（ROS1 Bag + Vector CAN BLF + DBC 定义）转化为统一的 SQLite 内存数据库（FrameStore），供下游分析模块查询。

包含 6 个子模块：BagParser、BlfParser、DbcLoader、TimeSync、FrameStore、CaseLoader。

---

## 1. BagParser — ROS1 Bag 解析

### 消息类型与字节结构

ROS Bag 中角雷达数据包含 4 种自定义消息类型，每种有不同的二进制布局：

#### wfAutosarData — AUTOSAR 雷达数据

每个目标固定 **36 字节**：

```
Offset  Size  Field            Type         Description
------  ----  -----            ----         -----------
 0       4    position_x       float32      纵向距离 (m)
 4       4    position_y       float32      横向距离 (m)
 8       4    velocity_x       float32      纵向相对速度 (m/s)
12       4    velocity_y       float32      横向相对速度 (m/s)
16       4    ttc              float32      碰撞时间 (s)
20       4    ttm              float32      侵入时间 (s)
24       4    classification   uint32       目标分类
28       4    width            float32      目标宽度 (m)
```

8 功能警告标志编码在 header 字段中（bitmask），每个 bit 对应一个 ADAS 功能的警告状态。

#### wfObjectMsg — 目标列表

每个目标固定 **185 字节**，包含完整目标属性：

```
Offset  Size  Field            Type         Description
------  ----  -----            ----         -----------
 0       4    timestamp        uint32       目标时间戳
 4       4    target_id        uint32       目标 ID
 8       4    x                float32      纵向距离
12       4    y                float32      横向距离
16       4    vx               float32      纵向速度
20       4    vy               float32      横向速度
24       4    ax               float32      纵向加速度
28       4    ay               float32      横向加速度
32       4    ttc              float32      TTC
36       4    ttm              float32      TTM
40       4    heading          float32      目标航向角
44       4    width            float32      目标宽度
48       4    length           float32      目标长度
52       4    rcs              float32      雷达截面
56       4    classification   uint32       分类标签
60       4    track_quality    uint32       跟踪质量
...                      ...              ... (其他字段)
184      4    warning_flags    uint32       8 功能警告标志 (bitmask)
```

#### egoCarInfo — 自车信息

固定 **69 字段**，包含：
- 自车速度、加速度
- 转向角、转向角速度
- 档位状态
- 8 功能使能状态（BSD/LCA/DOW/RCW/RCTA/RCTB/FCTA/FCTB）
- 系统运行状态
- 外部信号（手刹、灯光、AEB 状态等）

#### UInt8MultiArray — 报警原始字节

8 个 ADAS 功能 x 2 个方向（左/右）= 16 bytes 原始报警标志。

### 解析流程

```
.bag 文件
    │
    ▼
┌─ rosbags 读取 BagFile ───────┐
│  遍历所有 topic               │
│  过滤角雷达相关 topic          │
└──────────┬───────────────────┘
           │
           ▼
┌─ 按 topic 分发 ──────────────┐
│  /corner_radar/lgu_data_*    │→ wfAutosarData 解析器
│  /wf/objectlist_*            │→ wfObjectMsg 解析器
│  /wf/ego_car_info/*          │→ egoCarInfo 解析器
│  /warning_status_raw         │→ UInt8MultiArray 解析器
└──────────┬───────────────────┘
           │
           ▼
┌─ struct.unpack 反序列化 ─────┐
│  按消息格式拆解字节流         │
│  失败降级为 raw_hex           │
└──────────┬───────────────────┘
           │
           ▼
┌─ 标准化字段 ─────────────────┐
│  统一时间戳 (→ 秒)            │
│  统一坐标系                   │
```


### Warning Events 切分算法

原始报警字节是每帧的瞬时状态，需要将连续报警合并为事件：

```python
def _segment_warning_events(raw_bytes: list[tuple[float, bytes]]) -> list[WarningEvent]:
    """
    按 500ms 间隙对报警字节流进行切分。

    算法：
    1. 遍历所有帧的报警字节
    2. 对每个 ADAS 功能 + 方向组合，检测报警标志位变化
    3. 连续报警帧合并为事件
    4. 如果相邻报警之间的间隔 > 500ms，视为两个独立事件
    5. 如果间隔 < 500ms，合并为一个事件（忽略中间间隙）

    返回 WarningEvent 列表，每个包含：
        event_id, func_name, radar_id, start_time, end_time, duration
    """
    events = []
    for func_idx in range(8):
        for side in (0, 1):  # 0=left, 1=right
            byte_idx = func_idx * 2 + side
            current_event = None
            for ts, data in raw_bytes:
                if len(data) <= byte_idx:
                    continue
                is_active = bool(data[byte_idx])
                if is_active and current_event is None:
                    current_event = WarningEvent(start_time=ts)
                elif not is_active and current_event is not None:
                    gap = ts - current_event.end_time
                    if gap > 0.5:  # 500ms threshold
                        events.append(current_event.finalize())
                        current_event = None
                    # else: continue merging (short gap)
                elif is_active:
                    current_event.end_time = ts
            if current_event is not None:
                events.append(current_event.finalize())
    return events
```

## 2. BlfParser — CAN BLF 解析

### BLF 格式

Vector CAN 日志格式，包含多种事件类型：
- CAN Message (0x0002): 标准 CAN 帧
- CAN Error Frame (0x0003)
- CAN Driver Notification (0x0004)

本系统只处理 CAN Message 类型。

### 解析流程

```
.blf 文件
    │
    ▼
┌─ BLFReader 遍历 ─────────────┐
│  使用 python-can 库           │
│  逐帧读取                     │
└──────────┬───────────────────┘
           │
           ▼
┌─ 过滤 CAN Message ───────────┐
│  跳过 Error/Notification      │
│  提取: timestamp, can_id,     │
│        arbitration_id, data   │
└──────────┬───────────────────┘
           │
           ▼
┌─ DBC 解码 (可选) ────────────┐
│  使用 cantools 库             │
│  按 can_id 查找 DBC 定义     │
│  解码为信号字典               │
└──────────┬───────────────────┘
           │
           ▼
can_frames 行 → 写入 FrameStore
```

### API

```python
class BlfParser:
    def parse(self, blf_path: Path, dbcs: Optional[list[DbcDB]] = None) -> ParsedBlfData:
        """
        解析 CAN BLF 文件。

        Args:
            blf_path: BLF 文件路径
            dbcs: DBC 数据库列表 (用于解码信号)

        Returns:
            ParsedBlfData:
                can_frames:     list[dict] (can_frames 表数据)
                message_count:  int (总帧数)
                can_ids:        set[int] (出现的 CAN ID)
                start_time:     float (首帧时间戳)
                end_time:       float (尾帧时间戳)
        """

    def _decode_frame(self, frame: dict, dbcs: list[DbcDB]) -> dict:
        """
        使用 DBC 解码单个 CAN 帧。

        多 DBC 查找策略：
        1. 按 can_id (arbitration_id) 精确匹配
        2. 同一 can_id 可能存在于多个 DBC 中
        3. 收集所有 DBC 的解码结果，合并信号字典
        4. 信号名冲突时：最后一个 DBC 优先
        """
```

## 3. DbcLoader — DBC 加载

### 多 DBC 管理

系统支持同时加载多个 DBC 文件，覆盖不同的 CAN 网络：

| DBC 文件 | 覆盖范围 |
|---------|---------|
| CR_DBC_V3.2_20260331.dbc | 主 DBC（公 CAN） |
| GAC_CR_FR&FL_Private_CAN_V1.3.dbc | 前角私有 CAN |
| GWM_RearCorner_Pri_V3.0 (1).dbc | 后角私有 CAN |

### 加载流程

```
DBC 文件列表
    │
    ▼
┌─ cantools.database.load ────┐
│  逐个加载 DBC 文件           │
│  构建 Database 对象          │
└──────────┬───────────────────┘
           │
           ▼
┌─ 构建 ID 索引 ──────────────┐
│  can_id → [Database, ...]   │
│  同一 can_id 可能在多个 DBC  │
│  中定义（冲突记录）           │
└──────────┬───────────────────┘
           │
           ▼
list[DbcDB] → 供 BlfParser 使用
```

### API

```python
class DbcDB:
    database: cantools.database.Database  # 加载后的数据库
    file_path: Path                        # 原始 DBC 文件路径
    can_id_index: dict[int, list[str]]     # can_id → message_name 列表

class DbcLoader:
    def load(self, dbc_paths: list[Path]) -> list[DbcDB]:
        """加载多个 DBC 文件，返回 DbcDB 列表"""

    @staticmethod
    def decode_frame(database: Database, can_id: int, data: bytes) -> dict:
        """
        使用指定 DBC 数据库解码 CAN 帧。

        Returns:
            dict: {signal_name: value, ...}
        """
```

### 冲突处理

同一 frame_id 在多个 DBC 中定义时：
1. **先到者优先**：按 DBC 加载顺序，第一个匹配的定义优先
2. **信号合并**：不同 DBC 中不重叠的信号被合并
3. **冲突记录**：同名信号在不同 DBC 中有不同定义时，记录警告日志

## 4. TimeSync — 时间同步

### 问题

ROS Bag 和 CAN BLF 使用不同的时间基准：

| 数据源 | 时间格式 | 精度 | 示例 |
|--------|---------|------|------|
| ROS Bag | nanoseconds since epoch | 纳秒 | 1747584738000000000 |
| CAN BLF | Unix seconds | 微秒 | 1747584738.123456 |

### 对齐策略

#### 策略 1：首帧自动对齐（默认）

```python
def auto_sync(bag_start_ns: int, blf_start_s: float) -> float:
    """
    计算 BAG 到 BLF 的时间偏移。

    假设：两个录制设备的时钟差异 = (BAG首帧时间) - (BLF首帧时间)
    返回：offset_seconds (BAG 时间戳 + offset = BLF 时间戳)

    bag_time_synced = (bag_timestamp_ns / 1e9) + offset_seconds
    """
    bag_start_s = bag_start_ns / 1e9
    offset = blf_start_s - bag_start_s
    return offset
```

#### 策略 2：手动偏移

```yaml
# config.yaml
paths:
  time_sync:
    mode: manual
    offset_seconds: -0.123456  # 用户手动指定
```

### API

```python
class TimeSync:
    def __init__(self, mode: str = "auto", offset_seconds: float = 0.0):
        self.mode = mode
        self.offset_seconds = offset_seconds

    def align(self, bag_timestamp_ns: int) -> float:
        """将 BAG 时间戳对齐到 BLF 时间基准 (秒)"""

    def compute_auto_offset(self, bag_start_ns: int, blf_start_s: float) -> float:
        """自动计算时间偏移"""
```

## 5. FrameStore — SQLite 内存数据仓库

### 架构

```
FrameStore (:memory: SQLite)
├── bag_frames         -- ROS Bag 原始消息
├── can_frames         -- CAN 帧数据
├── radar_objects      -- 雷达目标 (解析后)
├── radar_debug        -- 自车状态 + ADAS 使能
└── warning_events     -- 报警事件 (切分后)
```

### 完整 DDL

```sql
-- 1. ROS Bag 原始消息
CREATE TABLE bag_frames (
    rowid INTEGER PRIMARY KEY,
    timestamp REAL NOT NULL,           -- 对齐后的时间戳 (秒)
    topic TEXT NOT NULL,               -- ROS topic
    msg_type TEXT NOT NULL,            -- 消息类型
    msg_data TEXT,                     -- JSON 序列化的消息数据
    radar_id INTEGER,                  -- 雷达 ID (1-4)
    raw_hex TEXT                       -- 原始 hex (解码失败时使用)
);
CREATE INDEX idx_bag_frames_time ON bag_frames(timestamp);
CREATE INDEX idx_bag_frames_topic ON bag_frames(topic);

-- 2. CAN 帧数据
CREATE TABLE can_frames (
    rowid INTEGER PRIMARY KEY,
    timestamp REAL NOT NULL,           -- 时间戳 (秒)
    can_id INTEGER NOT NULL,           -- CAN arbitration ID
    message_name TEXT,                 -- DBC 消息名
    signal_values TEXT,                -- JSON: {signal_name: value, ...}
    raw_data BLOB                      -- 原始 8 字节数据
);
CREATE INDEX idx_can_frames_time ON can_frames(timestamp);
CREATE INDEX idx_can_frames_id ON can_frames(can_id);

-- 3. 雷达目标 (核心分析表)
CREATE TABLE radar_objects (
    rowid INTEGER PRIMARY KEY,
    timestamp REAL NOT NULL,
    radar_id INTEGER NOT NULL,         -- 雷达 ID (1=FR, 2=FL, 3=RR, 4=RL)
    target_id INTEGER NOT NULL,        -- 目标跟踪 ID

    -- 位置 (相对自车, 米)
    position_x REAL,                   -- 纵向距离 (前方为正)
    position_y REAL,                   -- 横向距离 (左为正)

    -- 速度 (相对自车, m/s)
    velocity_x REAL,
    velocity_y REAL,

    -- 加速度 (m/s²)
    acceleration_x REAL,
    acceleration_y REAL,

    -- 目标属性
    ttc REAL,                          -- 碰撞时间 (秒)
    ttm REAL,                          -- 侵入时间 (秒)
    heading REAL,                      -- 航向角 (度)
    width REAL,                        -- 目标宽度 (米)
    length REAL,                       -- 目标长度 (米)
    classification INTEGER,            -- 目标分类
    track_quality INTEGER,             -- 跟踪质量
    rcs REAL,                          -- 雷达截面

    -- ADAS 警告标志 (bitmask: 8 功能)
    b_bsd_warning INTEGER,             -- 1=警告中, 0=无警告
    b_lca_warning INTEGER,
    b_dow_warning INTEGER,
    b_rcw_warning INTEGER,
    b_rcta_warning INTEGER,
    b_rctb_warning INTEGER,
    b_fcta_warning INTEGER,
    b_fctb_warning INTEGER,

    -- ADAS 使能状态 (从 egoCarInfo 填充)
    b_bsd_enable INTEGER,
    b_lca_enable INTEGER,
    b_dow_enable INTEGER,
    b_rcw_enable INTEGER,
    b_rcta_enable INTEGER,
    b_rctb_enable INTEGER,
    b_fcta_enable INTEGER,
    b_fctb_enable INTEGER
);
CREATE INDEX idx_radar_objects_time ON radar_objects(timestamp);
CREATE INDEX idx_radar_objects_radar ON radar_objects(radar_id);
CREATE INDEX idx_radar_objects_target ON radar_objects(target_id);
CREATE INDEX idx_radar_objects_func ON radar_objects(b_rcta_warning);

-- 4. 自车状态 + ADAS 系统状态
CREATE TABLE radar_debug (
    rowid INTEGER PRIMARY KEY,
    timestamp REAL NOT NULL,
    ego_speed REAL,                    -- 自车速度 (km/h)
    ego_accel REAL,                    -- 自车加速度 (m/s²)
    steering_angle REAL,               -- 转向角 (度)
    steering_rate REAL,                -- 转向角速度 (度/秒)
    gear_state INTEGER,                -- 档位 (0=P, 1=R, 2=N, 3=D)
    brake_pedal REAL,                  -- 制动踏板开度 (%)
    throttle_pedal REAL,               -- 油门踏板开度 (%)

    -- 8 功能使能状态
    b_bsd_enable INTEGER,
    b_lca_enable INTEGER,
    b_dow_enable INTEGER,
    b_rcw_enable INTEGER,
    b_rcta_enable INTEGER,
    b_rctb_enable INTEGER,
    b_fcta_enable INTEGER,
    b_fctb_enable INTEGER,

    -- 系统状态
    system_state TEXT,                 -- 当前系统状态字符串
    error_code INTEGER                 -- 错误码
);
CREATE INDEX idx_radar_debug_time ON radar_debug(timestamp);

-- 5. 报警事件 (预计算, 500ms 间隙切分)
CREATE TABLE warning_events (
    event_id INTEGER PRIMARY KEY AUTOINCREMENT,
    func_name TEXT NOT NULL,           -- ADAS 功能名 (BSD/LCA/...)
    radar_id INTEGER,                  -- 雷达 ID
    target_id INTEGER,                 -- 触发目标 ID (如果有)
    start_time REAL NOT NULL,          -- 事件开始时间 (秒)
    end_time REAL NOT NULL,            -- 事件结束时间 (秒)
    duration REAL,                     -- 持续时间 (秒)
    warning_type INTEGER,              -- 警告类型/级别
    gap_merged INTEGER DEFAULT 0       -- 1=通过 500ms 间隙合并
);
CREATE INDEX idx_warning_events_func ON warning_events(func_name);
CREATE INDEX idx_warning_events_time ON warning_events(start_time, end_time);
```

### 性能考虑

- **内存数据库**: 使用 `:memory:` SQLite，避免磁盘 I/O 瓶颈
- **批量插入**: 使用 `executemany()` 批量写入，单帧写入开销 < 1μs
- **索引策略**: 时间戳索引覆盖所有查询表，CAN ID 和消息名有独立索引
- **数据规模**: 典型案例 ~5 分钟录制，~180K CAN 帧 + ~50K 目标帧，内存占用 < 200MB

## 6. CaseLoader — 案例加载器

### 职责

统一入口：自动发现案例目录中的 .bag / .blf 文件，串联所有解析器，产出统一的 FrameStore。

### 加载流程

```
case_dir/
  ├── *.bag           (ROS1 Bag)
  ├── *.blf           (CAN BLF)
  └── *.dbc           (可选, DBC 定义)
        │
        ▼
┌─ CaseLoader.load_case() ────┐
│                              │
│  1. 扫描 .bag 文件           │
│  2. 扫描 .blf 文件           │
│  3. 扫描 .dbc 文件           │
│  4. 加载 DBC → DbcLoader     │
│  5. 解析 BAG → BagParser     │
│  6. 解析 BLF → BlfParser     │
│  7. 时间对齐 → TimeSync      │
│  8. 写入 → FrameStore        │
│                              │
└──────────┬───────────────────┘
           │
           ▼
CaseLoadResult:
    store:    FrameStore
```

### 自动发现规则

```python
def _discover_files(case_dir: Path) -> CaseFiles:
    bag_files = sorted(case_dir.glob("*.bag"))
    blf_files = sorted(case_dir.glob("*.blf"))
    dbc_files = sorted(case_dir.glob("*.dbc"))

    # 如果 case_dir 下没有 .dbc，尝试从 cases/ 根目录查找
    if not dbc_files:
        root_cases = case_dir.parent
        dbc_files = sorted(root_cases.glob("*.dbc"))

    # 多 bag/多 blf 支持：按文件名排序，依次加载并合并到同一 FrameStore
    return CaseFiles(bag_files, blf_files, dbc_files)
```

## 错误处理策略

| 场景 | 处理策略 |
|------|---------|
| Bag 文件损坏 | 跳过损坏消息，记录警告，继续处理其他消息 |
| 消息解码失败 | 降级为 raw_hex 存储，不中断解析 |
| BLF 读取失败 | 返回空 can_frames，bag 数据仍然可用 |
| DBC 加载失败 | CAN 帧以原始 hex 存储，无信号解码 |
| 时间对齐失败 | 使用默认 offset=0，记录警告 |
| 多 DBC 冲突 | 先到者优先，冲突信号记录日志 |
