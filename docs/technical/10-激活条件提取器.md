# ConditionExtractor — 激活条件提取器

## 职责

使用 AI 从 C 源码中精确提取 ADAS 功能的结构化激活条件，缓存到 JSON，供专家面板使用。

## 提取流程

```
1. 读取缓存: source_docs/{FUNC}_conditions.json
2. 检查源码是否变更 (mtime 对比)
3. 未变更 → 返回缓存
4. 已变更/首次 → AI 提取
5. 提取结果回填 CAN 信号名 (通过 signal_mapping)
6. 保存缓存
```

### AI 提取规则

1. **阈值必须给出具体数值** (从 float 初始化值读取)
2. **变量名必须与代码完全一致**
3. **区分进入/维持/退出报警** 的不同阈值
4. **只提取与当前功能直接相关的条件**
5. **必须提取外部抑制信号**:
   - 前向功能: AEB/ACC/ESP
   - 后向功能: 档位/R 档/转向灯/车门/驻车/DTC
   - 通用: 仪表开关/变型位屏蔽/DTC 故障码

### suppression_trigger 极性规则 (最重要)

```
suppression_trigger 必须填写导致功能退出/抑制动作发生/状态回退的值。

关键反直觉模式:
- if(!bXxxActiveFlg) { bKeepFunc=false; }
  → suppression_trigger='== FALSE', normal_value='== TRUE'
  (变量名含 Active 但 FALSE 才是抑制条件!)

验证方法: 将 suppression_trigger 代入 if 语句，
条件为真时代码执行抑制动作 → 极性正确
```

## 缓存机制

- 路径: `source_docs/{FUNC}_conditions.json`
- 失效: 源文件 mtime 更新
- 强制刷新: `force=True`

## 错误处理

- 源码不可用: 返回 `{"error": "源码不可用"}`
- AI 提取失败: 重试 2 次，最终返回原始响应
- JSON 解析失败: 重试或返回错误
