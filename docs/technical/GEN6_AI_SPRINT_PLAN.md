# Gen6 AI：Sprint 与集成交付计划

Sprint 按成果而非日历计时；不虚构开发天数。任务实际状态唯一来源为 [执行状态](gen6_execution_state.v1.json)，发布状态唯一来源为 [验收清单](release_acceptance.v1.json)。工作包 WP 与 Sprint 不同：WP 是责任域，Sprint 是跨模块可用成果。

## 1. 进出规则

进入条件：依赖已满足；任务卡明确 R/UX/AC、接口双方、真实输入、失败预期和验证；所需本地权限可用。远端权限未到位可做计划/本地部分，但不得将真实验收删掉。

退出条件：本 Sprint 必需任务完成、相关联调通过、用户可见演示可复现、证据/文档/状态一致、无影响该成果的关键缺陷。外部受阻时可明确记录 blocked 并推进不依赖分支，但 Sprint 不变成 accepted。

全程限制一个主集成切片；默认单 agent。没有用户或适用规则授权时不自动并行委派；即使以后允许，也按文件/接口所有权分工，跨模块集成由主执行者负责。

## 3. 各任务的具体输出

- T00：模块实现/缺口定位、实际分支/dirty 边界、可用环境和授权清单；不继续沿用文档旧值。
- T01：每项 AC 的测试层级/输入/判据/命令或步骤；人工耗时基线计划；gate 不允许空命令/空证据冒称通过。
- T10：材料→版本/车型/COEM→run 的真实入口；只有影响结果的冲突才询问。
- T11：数据索引复用、四雷达多事件/无报警定位、稳定事件和目标绑定、覆盖摘要。
- T12：plan/approval/attempt 的可恢复基础、独立工作区与资源所有权；避免后端边做边临时绕权限。
- T20：薄本地服务、revision/cursor、动作传回同一 Pi/run；路径访问和来源校验。
- T21：联动视图与代码变量数据，时间/几何证据分层；离线冻结导出。
- T22：真实浏览器的 loading/empty/partial/error/恢复、键盘/窄屏、重复动作，提交观察记录。
- T30：poll/cancel/reconcile、工作区互斥、重试与预算、未知执行状态处理。
- T31：当前宏/配置/binary 绑定的两种回放，reset/预热/ACK/完整采集；明确 GUI 差异。
- T32：真实同事件变量、赋值/消费链、GDB 缺失/扰动，证据到条件和结论；不硬编码个案。
- T33：真实 Pi 问题驱动选工具，工具发现可扩展，假设/反证与工程裁决；端到端跨模块验证。
- T40：有依据修改方案、预定义验证指标、授权 apply、保护原始工作区与变更恢复。
- T41：实际构建与回灌、可比较结果、同 bag 对照和局限，不能以单次报警消失冒称修好。
- T50：分段/端到端计时、冷/热缓存、近上限数据、tokens/内存/读取字节；修热点后同正确性回归。
- T51：variant/branch/customer freshness、反馈权限、按成功 scope 发布，状态更新后 prompt 拒旧知识。
- T52：UX01～11 人工对照，改善不省心的点；不得仅增加页面装饰。
- T60：单入口体检启动、依赖/adapter 版本、安装/升级/回退、磁盘/连接/模型故障支持。
- T61：所有必需 AC 的真实层级证据、完整本地回归、产品演示、发布 gate、已知局限和交付 handoff。

## 4. 可并行工作与禁止提前结案

逻辑上 T11 与 T12 可在 T10 后独立推进；T30 的执行控制与 T21 页面可先以冻结契约分别实现，但 S3 产品出口必须真实联调。T50 的计时从 S1 就开始，不等待 S5 才记录；T60 的依赖/安装约束在 S0 提前核对。

这只是依赖设计，不是自动启用并行 agent 的授权。mock 用于开发和契约，不替代真实 producer、浏览器、Pi 或 arbe 验收。界面占位不能作为完整能力交付。

## 5. Sprint 回顾

每个出口回答：用户现在多能做什么；哪些手工步骤消失；数字/代码是否准确对应；哪些失败能自恢复；新增模块是否重复；性能是否退化；下轮是否仍朝原目标。

记录证据和计划修订原因，必要时拆细任务但保留需求/AC；不能删除难验收项、把关键验证推到无限以后或为“进度”降低完成定义。
