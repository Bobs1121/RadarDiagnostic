## 1. 产品定位

radarAnalyze 是面向 **ADAS 角雷达功能/算法开发与测试数据分析工程师** 的**本地诊断 Harness**。核心价值：在功能异常（FCTA 未触发、迟滞、误触发等）出现时，**缩小排查范围**，输出**可追溯证据**与 **Top-3 根因候选**，辅助人工决策。**系统不自动宣判唯一根因**。

**边界**：
- 输出辅助决策，最终判定与修复由人完成。
- 数据不足是合法结果 —— 输出阶段性分析、unknown 项、待补采信号与验证建议，不强行下结论。
- 代码定位到逻辑/条件/参数/函数/调用链层面，不承诺每次精确到代码行。
- 确定性管线负责取证，Agent 仅做动态补查，不接管主流程。

## 2. 目标用户与场景

| 用户 | 场景 | 痛点 |
|---|---|---|
| 算法工程师 | 某次实车数据中 FCTA 应告未告 | 排查信号链、条件、参数耗时 |
| 功能开发工程师 | 新客户/新平台代码接入 | 不同代码仓信号/变量命名不同 |
| 测试数据分析员 | 大量 .bag/.blf/.mf4 数据 | 异构格式难统一查询 |
| 需求工程师 | 需求↔代码↔数据追溯 | 需求无法对到代码行与信号 |

---

## 3. 最小输入与输出

**最小输入（用户提供）**：问题与期望、录制数据(.bag/.blf/.mf4)、代码仓及分支、COEM、DBC、需求路径。

**每次诊断输出**：阶段性分析 / 关键数据(信号+时间窗+取值) / Top-3 候选 / 代码逻辑定位(source_refs) / unknown 项+原因 / 待补采信号 / 验证建议 / 可追溯工件。

---

## 4. 产品原则

1. **最小逻辑**：不引入新数据库/框架，优先复用已有零件。
2. **确定性取证优先**：主流程确定性取证与推理；Agent 仅动态补查。
3. **诚实标注不确定性**：区分 observed/inferred/unknown；数据不足即停步。
4. **历史知识必须重验**：只用于候选召回，必须经当前项目/分支/数据验证。
5. **插件化 = 一等公民**：新代码仓/新数据格式/新平台适配器/新记忆后端应**零改核心**接入。

> **ADR-PRD-1（决策冲突记录）**：用户于 2026-08-13 确认 Agent 定位为**真 ReAct 自主循环**（LLM 规划子步骤），与原则 2「Agent 仅动态补查」在字面上冲突。**调和**：ReAct 循环**包在固定 8 步管线之外**，每个行动仍调用确定性工具（DataProbe/TPE/CodeGraph），不改动确定性取证主流程。即「Agent 自主规划 → 确定性执行 → 结论仍由证据驱动」。此决策覆盖原则 2 中「不动态补查」的字面表述，但**不**推翻「确定性取证优先」。

## 5. 功能需求（FR）

### FR-1 诊断（M6 · 已实现）
- **FR-1.1** 8 步诊断管线：init→classify→extract→evidence→signals→diagnose→fix→deliver。
- **FR-1.2** 5 专家×3 轮 LLC 研讨，输出 Top-3 候选与证据链。
- **FR-1.3** 每条证据标注 observed/inferred/unknown。

### FR-2 自然语言查数（已实现）
- **FR-2.1** NL→信号查询，7 步流水线。
- **FR-2.2** 确定性调查层（investigation_engine）产出 ConditionCheck。

### FR-3 代码助手（实验）
- **FR-3.1** 无数据时查询代码结构/调用链/定义。
- **FR-3.2** 需求追溯（req→signal→function/file）。

### FR-4 数据浏览器（实验）
- **FR-4.1** 快速查询重时序数据，Plotly 可视化。
- **FR-4.2** 信号随时间变化视图。

### FR-5 记忆系统（已实现）
- **FR-5.1** L1-L6 分层记忆 + freshness 门控。
- **FR-5.2** Auto Dream 按 variant/customer 固化可复用知识。

### FR-6 项目接入（已实现）
- **FR-6.1** `project-init` 最小输入接入，自动生成 workspace/variant。
- **FR-6.2** Core/COEM 隔离与继承。

### FR-7 需求层（实验）
- **FR-7.1** YAML+Pydantic 结构化需求。
- **FR-7.2** 需求 Review（M8）。

### FR-8 代码 Review（实验）
- **FR-8.1** 修复建议 unified diff + clang 语法门。

### FR-9 插件化（🔴 核心新增需求）
- **FR-9.1** **新代码仓接入零改核心**：通过 `project-intake` + 配置即可，无需改代码。
- **FR-9.2** **新数据格式接入零改核心**：实现 Parser 插件 + 注册即可，无需改 `case_loader`。
- **FR-9.3** **新平台适配器接入零改核心**：实现 PlatformAdapter + 注册，分发 key 正确。
- **FR-9.4** **插件字段真正生效**：`codegraph_plugin/parser_plugin/symbol_ruleset` 必须分发。
- **FR-9.5** 插件注册/发现机制：装饰器注册 + 自动发现（见 31-software-architecture）。

## 6. 非功能需求（NFR）

### NFR-1 性能
- **NFR-1.1** GB 级数据可用（流式解析 + SQLite 批量插入）。
- **NFR-1.2** 单次诊断端到端可接受（KPI 度量）。

### NFR-2 可靠性
- **NFR-2.1** **fail-closed**：确定性知识缺失/过期不得进入 prompt。
- **NFR-2.2** 管线优雅降级，不崩溃；但**静默失败必须有可观性信号**（修 P0-1 后）。

### NFR-3 安全
- **NFR-3.1** 只读目标源码仓，不 checkout/fetch/pull。
- **NFR-3.2** 不自动修改源码/分支。
- **NFR-3.3** `asteval` 安全表达式，禁止 `eval`。

### NFR-4 可扩展性
- **NFR-4.1** 插件 SPI 统一（Parser/PlatformAdapter/SignalMapper/CodeGraphBackend/MemoryBackend）。
- **NFR-4.2** variant 沙盒隔离，杜绝跨项目知识串味。

### NFR-5 可维护性
- **NFR-5.1** AGENTS.md 与代码同步（修 P2-1）。
- **NFR-5.2** 消除孤儿/死代码（config 驱动）。

### NFR-6 可观测性
- **NFR-6.1** StepLogger/TokenTracker 记录每步与 token 消耗。
- **NFR-6.2** 静默失败必须告警（logging.warning → 结构化 observability）。

### NFR-7 平台
- **NFR-7.1** 零后台服务、纯本地、Windows 友好。

## 8. KPI

| KPI | 定义 |
|---|---|
| Top-3 命中率 | 真实根因落在 Top-3 内比例 |
| 错误确定结论率 | 系统给出确定结论但错误比例 |
| 代码定位准确率 | 候选函数/条件/参数定位正确比例 |
| 排查时间缩短比例 | 相比人工排查耗时缩短 |
| 诊断耗时 | 单次诊断端到端耗时 |
| **插件接入时间** | 新代码仓/格式/平台接入耗时（应显著 ↓） |

**首阶段目标**：在真实案例（CR60 Light）上跑通双向 trace 与 Top-3，Harness 度量上述 KPI，再迭代校准。

## 9. 验收标准

1. **signal→code**：从信号/时间窗出发，经内部变量、条件/参数，定位到函数/调用链，输出 Top-3+证据。
2. **code→signal**：从代码变量/函数出发，反查数据对应信号、时间窗与取值。
3. **数据不足输出 unknown**：关键信号缺失时输出阶段分析+unknown+补采建议，不强行下结论。
4. **报告可复核**：每条候选/证据可回溯到数据行/AST 节点/需求条目。
5. **插件化验收**：新增一个数据格式或平台适配器，**不改核心代码**即可接入并被诊断使用。
6. **P0 修复验收**：诊断报告 CodeGraph 上下文与代码修复建议**不再为空**。

## 10. 非目标 / 延期项

- **全自主 Agent 接管主流程**：ReAct 循环包在固定管线之外，不替换确定性 8 步管线（见 ADR-PRD-1）。
- LangGraph/ReAct 替代固定管线。
- 复杂图数据库（KùzuDB/LanceDB/DuckDB 按门槛触发）——**LanceDB 已确认启用**（见 ADR）。
- 实时文件监听 / 在线流式诊断。
- 自动修改源码/分支。
- 自动修复闭环 / 自动最终判定。
- 通用 Agent 平台。
- 精确到代码行的承诺。
